## Group #30 QueueSmart


### **Initial Thoughts**


`We are designing a web application.`

### Main Users of the Website
There will be 2 main users that will be using the website.

* **Client/Customer:** They will be using the website seeking for services and be in queue
* **Administrators:** They will act as staff or management operating the services

### User & Administrator Interactions

#### Users
* Log in to the website using email or phone number and a password.
* Select what service they need, join the queue, and see their wait time
* Receive live updates as their appointment time gets closer or is changed.
#### Administrators
* Manage the overall flow of the queue
* Update or delete customers' wait time
* Access usage analytics and data about operations



_Important Features_
User dashboard - Includes existing queues, personal information, and entering a new queue.
Entering a queue - This will ask for name and information as well as service options.
Email/Phone Notifications - For updates and reminders about queue wait time, cancellations, and changes.
Admin dashboard - Employees will see the queue line, how many people are in the queue, estimated time for each, and all user info. This will also allow the admin to change the wait time or cancel appointments.

Challenges:
Inaccurate wait times - If something goes wrong during an appointment or something takes longer than expected, the wait time may be inaccurate.
Notification delay/Undelivered - A queue update not being sent in time for the customer to see it or not being delivered at all leaving the customer not knowing updates or if they are correctly scheduled.
Overflow - A huge problem could come if there are too many people in the queue, many cancellations/changes, or unexpected delays and could cause the website to be slow or crash overall.




## Development Methodology

Our team decided to use Scrum as the development methodology for QueueSmart. Scrum is an Agile framework that divides development into shorter stages called sprints, allowing us to work on different features gradually instead of trying to build the entire system at once.

Scrum is a good fit for our group because we can divide the work into smaller tasks, assign responsibilities among team members, and regularly review our progress along the way.

Since QueueSmart will be built across multiple assignments, Scrum lets us build on what we finish in one stage as we move to the next. As we move from system design to UI/UX, API design, data design, and the final application, we can use what we completed earlier to plan and organize the next part of the project.
